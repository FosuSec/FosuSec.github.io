# 网站移动端适配
在「保留现有代码、只做加法」的前提下，实现网站完整移动端兼容，修复移动端错乱、横向滚动、交互异常、字体大小问题，输出响应式布局、视口、断点、字体缩放、交互处理方案。
## 何时使用
- 用户说「做移动端适配」「改成响应式」「手机页面乱了」「修复手机端bug」「手机字体太大/太小」
- 需要新增/修正网站移动端兼容逻辑、调试小屏布局、优化触摸交互、适配移动端字号
- 目标是多设备可用，不推翻原有PC端业务逻辑样式
## 核心心法
1. **只做加法，最小侵入**：原有样式全部保留，新增样式做叠加补充，不大规模重构业务代码。
2. **视口优先原则**：必须校验viewport元标签，视口缺失是移动端绝大多数错乱根源。
3. **单位与断点规范化**：优先相对单位，统一媒体查询断点，二选一移动优先/PC优先模式，不要混用两套断点。
4. **字号分层适配**：PC/平板/手机区分标题、正文、辅助文字字号，禁止小屏出现过大标题或过小正文。
5. **交互贴合移动端特性**：规避hover依赖、保证触摸热区尺寸，处理iOS特有兼容坑。
6. **真实设备优先验证**：模拟器仅作辅助，修改完成后需要真机核验。
## 需要规避的问题黑名单（务必避免）
- 缺失或错误配置 meta viewport，页面整体缩小、禁止缩放未按需配置
- 大量硬编码固定px宽度，造成页面横向滚动溢出
- 完全依赖CSS hover实现关键交互，移动端点击行为异常
- 未重置iOS表单、点击高亮、默认圆角，出现原生样式错乱
- 全局字号写死固定px，手机端标题溢出屏幕、正文文字过小阅读困难
- rem/vw无上下限，极小屏字体过小，平板大屏字体过大
- 布局混用两套媒体查询逻辑（同时写min‑width和max‑width两套断点）
## 推荐实现手法（按场景选用）
### 基础页面底座
- **标准视口meta**：head内注入规范viewport标签，按需配置电话识别、webapp相关meta。
- **全局CSS盒模型重置**：统一box-sizing，清除ios点击灰块，图片自适应规则，表单原生样式抹平。
- **响应式断点集**：提供两套模式：移动优先(min‑width) / 老项目PC优先(max‑width)，统一断点阈值：768px、1024px、1280px。

### 🔤 字体大小适配（移动端重点）
- **字号分层体系**：区分大标题、标题、正文、辅助小字；移动端**降低标题字号，保证正文可读性，辅助文字不能小于12px**。
- **相对单位优先**：优先使用`rem`；慎用纯`vw`，必须设置字号上下限，防止极端屏幕字号崩坏。
- **CSS变量管理字号**：把各级字号定义为css变量，不同断点下修改变量，不要到处写重复font‑size。
- **JS rem基准控制**：动态设置html根字号，同时设置根字号最大、最小限制，避免超大屏字体爆炸、极小屏文字挤成一团。
- **行高同步适配**：移动端行高适度放大，提升小屏阅读舒适度，标题行高适当收紧。

> 示例变量思路：
> ```css
> :root {
>   --fs‑h1: 3rem;
>   --fs‑h2: 2.25rem;
>   --fs‑body: 1rem;
>   --fs‑small: 0.875rem;
>   --lh‑body: 1.6;
> }
> /* 手机端覆写变量，不改动原有DOM选择器 */
> @media (max‑width:767px) {
>   :root {
>     --fs‑h1: 2rem;
>     --fs‑h2: 1.6rem;
>     --fs‑body: 0.9375rem;
>     --fs‑small: 0.8125rem;
>     --lh‑body: 1.7;
>   }
> }
> ```

### 布局适配
- **Flex弹性换行**：`flex-wrap: wrap` + `flex:1 1 min‑宽度`，卡片、导航自动换行，适合列表模块。
- **Grid自动填充**：`grid-template-columns: repeat(auto-fit, minmax(xxx, 1fr))`，无需媒体查询自动适配列数。
- **Rem动态根字号**：JS监听resize动态设置html根字体，适配设计稿，设置最大最小字号阈值防止极端屏幕异常。

### 移动端交互处理
- **条件hover**：使用`@media (hover:hover)`包裹hover样式，仅桌面端生效，规避移动端hover残留。
- **触摸热区规范**：可点击元素最小尺寸≥44px，保证手指点击容错。
- **汉堡导航降级**：PC横向导航，小屏收起为汉堡按钮，弹窗呼出导航菜单。

### 多媒体资源适配
- **视频/iframe等比容器**：aspect‑ratio实现固定比例容器，内部媒体100%填满容器。
- **图片max‑width:100%**，height:auto，防止图片溢出容器。

## 技术纪律（每一条都很重要）
- **深浅色模式兼容**：新增样式复用已有的CSS变量，禁止硬编码颜色。
- **无障碍动效兜底**：动画、过渡效果必须增加`@media (prefers‑reduced‑motion: reduce)`降级关闭。
- **字号无障碍底线**：移动端正文字号不低于**12px**；标题缩小但不能完全丧失层级；禁止纯vw不设min/max限制字号。
- **多语言同步**：中英双语站点适配逻辑两边同步修改，不能只改单端。
- **防FOUC闪烁**：滚动类动态效果，head提前注入js标记类，避免页面闪烁。
- **JS兼容优先**：复杂布局计算、尺寸监听优先JS，不要过度依赖跨浏览器不一致的CSS特性。

## 常见坑与修复对照
| 症状 | 根因 | 修复 |
|------|------|------|
| 手机打开页面整体缩小 | viewport缺失或者配置错误 | head添加完整正确的viewport meta标签 |
| 移动端出现横向滚动条 | 存在固定大宽度元素、padding未被盒模型收纳 | 设置box‑sizing:border‑box，给溢出元素设置max‑width:100% |
| iOS点击有灰色半透明遮罩 | webkit默认点击高亮 | 设置 `-webkit‑tap‑highlight‑color: transparent` |
| iOS输入框点击页面放大 | viewport未限制maximum‑scale | meta标签设置maximum‑scale=1.0 |
| hover点击之后样式停留不消失 | 移动端没有鼠标hover概念 | hover逻辑放入`@media (hover:hover)`媒体查询 |
| fixed定位弹窗被输入法顶错位 | iOS下fixed受虚拟键盘影响 | 改为absolute定位或者增加键盘高度JS判断 |
| 手机大标题文字超出屏幕、换行混乱 | PC端h1/h2字号未做移动端降级 | 通过媒体查询/CSS变量，小屏降低标题字号，适度调整行高 |
| 手机上文字看着很小，阅读吃力 | 正文字号写死PC px值，未适配小屏 | 使用rem相对单位，移动端覆写字号变量，正文不低于12px |
| vw字体在极小屏过小 / 平板过大 | 直接font‑size用vw无边界 | 使用clamp()或者CSS变量+媒体查询设置字号上下限 |

## 流程建议
1. 先检查现有页面：viewport、已有断点、全局CSS变量，确认当前是移动优先还是PC优先，梳理现有标题/正文字号。
2. 挑选2‑4处关键模块迭代修改，优先处理标题、正文字号，不要一次性写大量适配代码。
3. 双语站点两边同步更新样式。
4. 构建项目确认无报错，优先真机预览验证字号与布局。
5. 向用户简述改动点，保留回退、调整断点阈值、微调各级字号的修改空间。
